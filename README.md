# Enterprise Work Assistant

NVIDIA AI CAMPUS 팀 프로젝트 — LLM 기반 제안요청서 요구사항 그룹화 및 요약 서비스

## 프로젝트 목적

제안요청서(RFP)에 포함된 중복되거나 유사한 요구사항을 식별하고, 관련 내용을 묶어 목록화하여 핵심 요구사항을 한눈에 파악할 수 있도록 지원합니다. 문서에 흩어진 내용을 반복해서 확인하는 부담을 줄이고, 공통점과 차이를 쉽게 확인하도록 돕습니다.

> 주제와 역할 분담을 확정했습니다. 현재 Python 파일은 담당 기능을 설명하는 주석만 포함하며 실제 기능은 아직 구현하지 않았습니다.

## 프로젝트 정의

- **입력:** 텍스트 추출이 가능한 PDF 및 HWP 형식의 RFP
- **처리:** 문서 형식별 텍스트 추출 → 요구사항 구조화 → 파인튜닝한 LLM으로 중복·유사 관계 식별 → 그룹화 → 핵심 내용 요약 및 목록화
- **출력:** 그룹명, 요약, 포함된 요구사항, 보존할 차이점, 원문 위치를 담은 정리표와 CSV

유사한 요구사항을 묶더라도 서로 다른 조건과 제약사항을 유지합니다. 원문을 삭제하거나 임의로 하나의 요구사항으로 확정하지 않습니다.

## 주요 기능

1. **요구사항 추출 및 구조화:** PDF·HWP에서 요구사항을 추출하고 ID와 원문 위치를 기록합니다.
2. **중복·유사 요구사항 그룹화:** 관계 분류를 바탕으로 관련 항목을 묶습니다. 애매한 항목은 단독으로 유지합니다.
3. **그룹별 요약 및 목록 제공:** 핵심 내용과 차이점을 원문 근거와 함께 표시하고 CSV 다운로드를 제공합니다.

| 관계 분류 | 기준 |
| --- | --- |
| 중복 | 표현이 달라도 핵심 요구와 주요 조건이 실질적으로 같음 |
| 유사·관련 | 같은 기능이나 주제를 다루지만 범위·조건·제약에 차이가 있음 |
| 무관 | 함께 묶을 근거가 부족함 |

## 역할 분담

| 구분 | 팀원1 — 데이터 검증·평가 | 팀원2 — 문서 처리·화면 | 팀원3 — 모델 학습·통합 |
| --- | --- | --- | --- |
| **직접 구현할 기능** | 학습 데이터 검사 및 평가 점수 계산 | PDF·HWP 텍스트 추출, 업로드·결과 화면 | QLoRA 학습, 관계 분류, 그룹화·요약 |
| **주요 입력** | 정답 CSV, 모델 예측 CSV | PDF·HWP 파일, 결과 JSON | 요구사항 데이터, 추출 텍스트 |
| **주요 출력** | 데이터 오류 목록, 정확도·Macro F1 | 추출 텍스트, 결과표, 다운로드 CSV | 관계 판정, 그룹별 요약, 학습된 Adapter |
| **금요일 완료 기준** | 샘플 CSV로 검사와 평가 실행 | PDF·HWP 샘플 처리 및 샘플 결과 화면 실행 | 기본 모델 추론 및 짧은 학습 시험 완료 |

## 담당 파일 및 구조

```text
src/

  inference.py         # 팀원3: 요구사항 구조화 및 관계 분류 추론
```

## 활용 데이터

- **출처 후보:** 공공기관 홈페이지·나라장터 등에 공개된 IT 시스템 구축 RFP. 실제 문서와 이용 조건은 확인 후 선정합니다.
- **확보 목표:** RFP 2~3개, 요구사항 쌍 200~300건. 현재 확보량이 아닌 계획 수량입니다.
- **형식:** 원본 PDF·HWP, 정답 CSV, 학습용 JSONL
- **주요 항목:** 사례 ID, 요구사항 A·B ID와 원문, 관계 분류, 판단 근거, 보존할 차이점

원본 요구사항을 먼저 학습·검증·평가로 분리한 뒤 각 분할 안에서 쌍을 구성합니다. 같은 요구사항과 변형 사례가 학습·평가에 겹치지 않도록 하며, 가능하면 문서 단위로 분리합니다. 초기 분할 비율은 약 70%·15%·15%를 검토합니다. 평가 정답은 사람이 확인합니다.

## 문서 처리 및 연결 원칙

- PDF는 페이지 번호를, HWP는 확보 가능한 절·문단·표 위치를 보존합니다.
- HWP를 PDF로 변환해 처리한다면 페이지 번호가 변환본 기준임을 표시합니다.
- 공통 문서 전달 항목: 문서명, 문서 형식, 원문 위치, 추출 텍스트
- 결과 화면 전달 항목: 그룹 ID, 그룹명, 요약, 포함 요구사항 ID, 차이점, 원문 위치
- 구체적인 JSON 필드명과 함수 인터페이스는 개발 시작 시 합의합니다. 화면은 샘플 JSON으로 먼저 구현할 수 있습니다.
- 연쇄적인 유사 관계만으로 항목을 무조건 합치지 않고, 그룹 전체의 관련성을 확인합니다.

## 완성 목표와 범위

### 3일 뒤 시연할 결과물

- 관계 분류를 학습한 QLoRA Adapter
- 문서 업로드부터 그룹화·요약·CSV 저장까지 연결한 로컬 웹 서비스
- 동일 평가 데이터에 대한 파인튜닝 전후 성능 비교

### 성공 기준 — 제안 목표치

| 항목 | 목표 |
| --- | --- |
| 문서 입력 지원 | PDF·HWP 샘플 각 1개 이상에서 요구사항 텍스트 추출 및 원문 대조 |
| 전체 흐름 완성 | 샘플 RFP의 요구사항 10~20개를 추출·그룹화·요약하고 CSV로 다운로드 |
| 관계 분류 성능 | 미사용 평가 세트에서 3개 분류의 Macro F1 0.75 이상 |
| 학습 효과 | 동일 기본 모델 대비 파인튜닝 후 Macro F1 0.05 이상 향상 |
| 추적 가능성 | 추출한 요구사항 모두를 그룹 또는 단독 항목으로 표시하고 원문과 연결 |
| 요약 충실성 | 팀이 지정한 핵심 조건·제약의 90% 이상을 요약 또는 차이점 항목에 보존 |
| 처리 시간 | 모델 로딩을 제외하고 요구사항 20개의 그룹화·요약을 3분 이내 완료 |

목표치는 첫날 실행 시험을 바탕으로 본 학습 전에 확정합니다. 미달 결과와 한계도 그대로 기록합니다.
